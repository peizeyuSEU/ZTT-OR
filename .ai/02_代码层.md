# 代码层 — 模块结构、类职责、接口与数据流

## 系统层级总览

```
第0层  实验配置层      实验方案：规模组合、δ值列表、对比实验定义
第1层  启动器          main入口：读实验配置，按方案编排运行流程
第2层  参数配置层      Config：问题参数、算法参数、公式开关
第3层  公式计算层      ①~⑨ 论文公式，独立可验证，纯函数
第4层  求解算法层      GA → BP → CG → PS + BB，调公式层算数
第5层  结果输出层      后处理 + 报告 + 收敛曲线

基础层  日志/监控/随机数/CPLEX  Logger, Metrics, Random, CplexWrapper
```

## 各层级详细说明

### 第0层 — 实验配置层（0_experiments/）

**职责**：定义要运行哪些实验，每个实验覆盖哪些变量组合。

**当前状态**：✅ 已实现（YAML格式，单文件包含所有参数 + 实验列表）

**设计思路**：
- 每个 YAML 文件 = 一组实验（如论文表4.1的5组规模）
- 文件顶部是全局默认参数（所有 Config 支持的字段）
- `experiments:` 段下面列出每个实验条目
- 每个条目只需要写**要覆盖的字段**，其余继承全局默认值
- 不再需要 JSON + YAML 两套解析

**覆盖规则**：
```
experiments/table4_1.yaml
  ↓ Config 加载
读取全局默认字段到 Config 对象
读取 experiments 列表到 Config.experiments
  ↓ run.cpp 遍历
对每个条目：
  Config runnerConfig = planConfig           // 复制全局默认
  runnerConfig.applyEntry(entry)             // 用条目的 overrides 覆盖
  ExperimentRunner::run(runnerConfig, ...)   // 运行
```

**示例** `table4_1.yaml`:
```yaml
num_dc: 3
num_retailers: 10
population_size: 30
max_generation: 50
delta: 5000
experiments:
  - name: "scale_3_5"
    num_dc: 3
    num_retailers: 5
  - name: "scale_3_10"
    num_dc: 3
    num_retailers: 10
```

**可覆盖字段**：Config.h 中所有字段（num_dc, num_retailers, population_size, max_generation, crossover_rate, mutation_rate, delta, carbon_price, carbon_cap, random_seed, holding_cost, ...）

### 第1层 — 启动器（1_launcher/）

**职责**：读取第0层的实验方案，按方案编排运行流程，不包含业务逻辑。

**当前状态**：✅ 已实现，分为单次运行和批量运行两条路径

**文件职责**：
- `main.cpp` — 单次运行：读根目录 config.yaml → 生成数据 → 求解 → 输出
- `ExperimentRunner.h` — 运行引擎：封装"生成数据→基准方案→GA求解→后处理→输出"的标准流程

**启动器不应该包含**：
- 具体的实验参数（应该在第0层或第2层）
- 公式计算逻辑（应该在第3层）
- 算法的具体实现（应该在第4层）

### 第2层 — 参数配置层（2_config/Config.h + config.yaml）

**职责**：所有参数的读取和管理。支持从 YAML 加载，包括全局默认值和 experiments 列表。

**当前状态**：✅ 已实现

**关键特性**：
- 支持 `experiments:` section 解析（含缩进、列表 `- item`）
- `ExperimentEntry` 结构体：`name` + `overrides` (map)
- `applyEntry()` 方法：将条目的 overrides 合并到 Config
- 所有字段在 `setField()` 中注册，新增字段只需加一行即可生效

**关键参数**：
```yaml
# 公式模型选择
use_sqrt_investment: true        # true=½δw²√D（论文版） false=½βw²（旧版）
holding_cost: 10.0               # 论文表5-1中 h=10
```

## 公式层各文件

### 01_Revenue.h — 收入
```
r_i(p_j) = p_j  (p_j ≤ v_i) 或 0 (p_j > v_i)
收入 = Σ_i r_i(p_j) * μ_i * Y_ij
```

### 02_FacilityCost.h — DC固定成本 + 固定碳排放成本
```
DC固定成本 = f_j * X_j
DC固定碳成本 = p̂ * f̂_j * (1-w_j) * X_j
```

### 03_TransportCost.h — 运输成本 + 运输碳排放成本
```
供应商→DC运输成本 = c(a_j) * D_j
供应商→DC运输碳排放成本 = p̂ * b̂_j * (1-w_j) * D_j
DC→零售商运输成本 = Σ_i c(d_ij) * μ_i * Y_ij
DC→零售商运输碳排放成本 = Σ_i p̂ * b̂_ij * (1-w_j) * μ_i * Y_ij
```
其中 c(a_j), c(d_ij) 为分段函数（论文式5-1,5-2）

### 04_InventoryCost.h — 库存成本（EOQ代入后）+ 安全库存成本
```
库存持有成本 = √(2*(F_j+g_j)*(h + p̂*ĥ*(1-w_j))*D_j)
安全库存成本 = (h + p̂*ĥ*(1-w_j)) * z_α * √(L_j * Σσ²_i)
```
**注意**：EOQ消掉了 Q_j，这里已经是代入后的形式

### 05_InvestmentCost.h — 减排投资成本
```
投资成本 = ½ * δ * w_j² * √D_j
```
**公式开关**：可通过配置切换为 `½ * β * w_j²`（旧版）

### 06_CarbonCredit.h — 碳配额收入
```
碳配额收入 = p̂ * C（常数项）
```

### 07_Constraints.h — 约束条件
```
碳约束：E * (1-w_j) ≤ C + e⁺ - e⁻
唯一分配：Σ_j Y_ij ≤ 1, ∀i
DC开设：Y_ij ≤ X_j, ∀i,j
```

### 08_Objective.h — 总目标函数
```
R̄_{j,S} = 01_Revenue
         - 02_FacilityCost
         - 03_TransportCost
         - 04_InventoryCost
         - 05_InvestmentCost
         + 06_CarbonCredit
```
即论文式4-2的 R̄_{j,S}

### 09_PostCompute.h — 后处理反算
```
Q_j* = √(2*(F_j+g_j)*D_j / (h + p̂*ĥ*(1-w_j)))  ← EOQ反算
E    = 设施碳排放 + 运输碳排放 + 库存碳排放（含安全库存）
e⁺  = max(E - C, 0)
e⁻  = max(C - E, 0)
```

## 模块职责与关键接口

### Config.h（第2层）
- 从YAML文件读取参数
- 内置轻量级解析器（无外部依赖）
- 关键方法: `loadFromFile()`, `print()`, `saveToFile()`

### Instance.h（核心数据）
- 存储所有输入数据
- 关键方法: `setEmissionReductionRates(w_values)`

### Types.h（核心数据）
- `PricingResult`, `CGResult`, `BranchState`, `DCSolution`, `Solution`, `ConvergencePoint`

### DataGenerator.h（数据层）
- standard模式：Mersenne Twister，论文参数
- legacy模式：线性同余生成器，原代码兼容
- 关键方法: `generate(config)` → Instance

### PricingSolver.h（第4层）
- 给定对偶变量，找使检验数最大的 (j, S, p_j)
- 候选价格 = 各零售商保留价
- 凸包枚举 O(n³)
- 关键方法: `solve(j, dual)` → PricingResult

### ColumnGeneration.h（第4层）
- 动态加列，不重建模型
- 关键方法: `solve(branchState)` → CGResult

### BranchAndBound.h（第4层）
- DFS，剪枝条件：LP解 ≤ bestLowerBound
- 关键方法: `solve()` → 最优目标值

### BranchAndPrice.h（第4层）
- 缓存（key=w向量，最多100条）
- 关键方法: `solve(w, label)` → 适应度

### GeneticAlgorithm.h（第4层）
- 二进制编码10位，精英保留，轮盘赌，两点交叉
- 关键方法: `run()` → Solution

### PostProcessor.h（第5层）
- 调 09_PostCompute.h 反算

### CplexWrapper.h（基础层）
- RAII管理 IloEnv

```
    ↓

    ↓
0_base/01_types/Instance          ← 问题实例
    ↓
┌──────────────────────────────────────────────────┐

│  01~08 → R̄_{j,S}  ← 算法层每次评估调这里         │

    ↑ 调用

│  第4层：4_algorithm/                              │

│  02_ResultWriter → report.txt                    │

```
