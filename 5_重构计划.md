# 重构计划：4_重构代码 → 5_重构代码v2

## 目标

新建 `5_重构代码v2/` 目录，按照架构设计.md 重新组织代码结构，**保证输出结果与 `4_重构代码/` 完全一致**。

## 验证方法

用相同的 `config.yam
l`（同一种子 32501）分别跑两个版本，对比：
- totalProfit
- 碳排放
- 最优 w 值
- 收敛曲线

## 实施步骤

### Step 1：创建目录结构
在 `5_重构代码v2/` 下创建所有空目录。

### Step 2：原样迁移 7_formula/（9个文件）
纯函数，不需要改，原样复制。

### Step 3：迁移 10_common/（Types.h, Solution.h, Instance.h, Config.h, Random.h, ThreadPool.h）
- Config.h：加 `run_mode`、`fixed_w` 字段
- 新增 `OutputManager.h`

### Step 4：迁移 4_logger/、3_monitor/、5_result/
- Logger：从 base 移出，接口不变
- Monitor：Metrics 升级版，加上 reportGeneration/reportPhase 等
- ExperimentResult.h + ResultWriter.h：新的结果模块

### Step 5：迁移 6_preprocessor/（Instance.h, DataGenerator.h, DataLoader.h）
Instance.h 从 base 移入。

### Step 6：迁移 8_solver/（算法层5个文件 + CplexWrapper + 策略接口）
算法逻辑完全不变，只改 include 路径。新增策略接口（不修改算法本身）。

### Step 7：迁移 9_postprocessor/
原样迁移。

### Step 8：新增 2_orchestrator/（Orchestrator.h + StrategyFactory.h）
Orchestrator 替代 ExperimentRunner，三阶段生命周期。

### Step 9：迁移并改造 1_launcher/ 和 0_experiments/
- main_single.cpp：绝对路径引用
- main_batch.cpp：使用 ExperimentPlan + OutputManager

### Step 10：Build.mk + Makefile + config.yaml
- 更新 include 路径
- 根目录 config.yaml 放在 5_重构代码v2/ 下
